  4. Kasper

    I would start by mapping how product data moves from source to finished copy: Where is information reused, where do errors occur, and which steps require professional judgement? From there I would pick one well-defined task to automate.

    At VoiceArchive I built an n8n flow that created 320 landing pages from structured data. That experience could be relevant for you: If product copy in several languages is a time-consuming task, a first flow could create drafts with master data as the source and expert approval before use.

  5. Thomas · Maki

    A solution is only worth something once it is used. How do you get colleagues on board?

  6. Kasper

    By building it together with them. I start with one concrete task that they themselves find tedious and make the simplest version that works. Once it is in use, I measure what it saves and adjust based on their feedback.

    The systems I have built are still in use because they were built together with the users and have been adjusted continuously based on their feedback. Documentation and short training sessions are a standard part of the delivery, so the solution does not depend on me.

  7. Thomas · Maki

    What about LLMs, APIs and MCP?

  8. Kasper

    I know LLMs, APIs and MCP well enough to use them properly and, more importantly, to know their limits. An LLM is strong at structuring, writing and summarising, but it must never guess when data is missing. That is why I always connect it to the right source through APIs or MCP.

    In practice it ranges from something as simple as automated email replies to the Search Console API, which keeps a constant eye on Google rankings. With a WordPress MCP I can easily create pages and handle the small but time-consuming fixes. I also have MCP connections in production for Meta Ads, Gmail, analytics and content production, among others.
